## 部署前验证

```bash
npm ci
npm run check
npm test
npm run deploy -- --dry-run
```

最后一条只打包，不创建远端数据库、不修改云密钥、不发布。

生产需要 Node 的只有开发工具，Worker 本身使用 Web 标准 API。应用本地预览依赖 Node 24.15+ 的内置 SQLite（该接口仍处于 release candidate）；生产使用 D1，并不使用本地 SQLite 适配器。

## 查房网站部署

先通过官方 Wrangler 完成一次登录：

```bash
npx wrangler login --scopes account:read user:read workers:write workers_scripts:write d1:write
npm run deploy
```

`deploy` 会检查当前账号、复用或创建同名 D1、应用增量迁移、部署页面和 Worker、保存公网地址，并在缺失时生成应用密钥。密钥通过 stdin 传入 Wrangler，不出现在命令参数或源码中。重复运行会复用已配置数据库与 APP_SECRET，不自动轮换。

邀请模式首次部署后还需运行一次 `npm run invites -- --remote`，生成和绑定首批名额；后续普通部署不需要重建邀请码。初始化未完成时，新建提醒会拒绝访问，公开查房仍可用。已有本机私有邀请码文件必须保留，流程见[邀请说明](invitations.md)。

登录仅请求账号/用户读取、Workers、脚本发布和 D1 所需权限，以及官方工具自动加入的后台访问。`workers:write` 不能代替 `workers_scripts:write`；缺少后者可能成功创建数据库，但无法上传网站。不要为消除 Wrangler 的全部可选权限警告而一次开启其他产品权限。

这个命令会写入当前 Cloudflare 账号并公开发布，应在拥有者确认上线后运行。代码的提交和推送需要单独确认。

## 接通邮件

需要的配置：

| 名称 | 用途 |
| --- | --- |
| `APP_SECRET` | 待发邮件加密；首次部署自动生成，后续保留 |
| `BREVO_API_KEY` | Brevo 服务端 API 密钥 |
| `MAIL_FROM` | 已在 Brevo 验证的发件邮箱 |
| `PUBLIC_URL` | 网站正式 HTTPS 地址；部署脚本保存到 Wrangler vars |

发件邮箱和 API 密钥应在安全环境中提供，再执行 `npm run deploy -- --with-mail`。部署命令会自动读取本机被 Git 忽略的 `.env.local`；可在该文件填写 `BREVO_API_KEY` 和 `MAIL_FROM`，并将文件权限设为 `0600`。不要把密钥粘贴进聊天、提交到 Git，或写在 shell 命令参数中。配置通过 stdin 设置为 Cloudflare secrets。

密钥配置成功只证明配置已保存，健康检查的 `mailConfigured:true` 只代表字段齐全。上线验收要真正走一遍：建立提醒 → 收到验证邮件 → 点击页面确认 → 看到启用状态 → 测试有房通知 → 暂停/取消 → 确认不会继续发送。

## 后台任务与额度

邀请制之前的版本 `a395ca1b` 的实际样本（2026-10-13，UTC+8）：14:36 采集 7 个日历 CPU 30ms，14:37 精简日历 HTTP CPU 13ms，outcome 均为 ok。仍超过免费档 10ms，不能承诺长期稳定；拥有者已决定继续免费邀请内测，没有付费升级。邀请制控制参与规模，不能消除单次 CPU 超限。

使用三个独立 Cron，避免同一次任务累积超过免费 D1 查询预算：

- 每 2 分钟：生产 Worker 最多 20 次官网请求的采集批次，每轮最多刷新一类目录，日历按站点共享。
- 每分钟：最多检查 3 条到期提醒、发送 2 封待发邮件；每条提醒自身的检查间隔为 15 分钟。
- 每日 UTC 19:00（上海次日 03:00）：清理过期记录。

官网数据默认 15 分钟刷新、20 分钟后视为过期。按平均频率折算，每 15 分钟约有 150 次采集请求预算；重试、超时和任务分布会占用预算，不能据此承诺所有站点和区间均在 15 分钟内刷新。首次全市数据需要多个批次；网页会展示已有可靠结果和待确认部分。

用户已确认的免费首发范围：5 个受邀邮箱、每人最多 2 条占位提醒，总上限 10 条；待验证、启用和暂停的有效提醒占名额。单日可关注全市，连续入住提醒必须选择具体驿站，普通连续入住查询仍可按区域/全市查找。应用每日邮件发送尝试最多 250 次、每邮箱每天最多 8 次有房通知，验证与管理邮件也占总预算。平台账户可能还存在其他用量，不承诺一定覆盖实际流量。初始化和分发见[邀请说明](invitations.md)。

公开区间查询按 IP 和全站限流；最多 300 个区间采集任务，公开查询最多占 260，保留 40 给已验证提醒。提醒任务优先，任务重复入队不清除退避状态。

普通区间查询采集成功后释放任务名额，快照继续保留；已验证提醒的任务继续按周期刷新。公开查询仅补缺失、过期或无效的快照，不因页面重试重复采集新鲜数据。新任务入队时也会回收旧版本遗留的已完成普通任务。日历与区间都有待处理任务时均分剩余请求预算，同优先级和到期时间下先处理较早入队的任务。队列容量受限时仍可返回已有结果，页面会显示更新进度与未入队状态，不保证全市多个不同入住区间同时即时完成。

## 运维和恢复

- 通过 `/api/health` 检查服务版本；用页面采样时间、部分结果和覆盖率检查数据是否更新。
- 使用 Cloudflare 的 Cron 事件和 Worker 日志查看稳定错误分类，禁止记录请求正文、完整令牌或邮件地址列表。
- D1 备份/恢复使用平台能力；恢复前暂停通知，确认时间范围，防止状态回退后重复发送。
- 已应用 SQL 迁移保持不变，后续 schema 修改必须新增迁移。
- APP_SECRET 需安全保留；轮换会使旧的待发加密邮件无法解密。不要为普通更新重新生成。
- 回滚 Worker 代码前先确认它兼容当前数据库 schema；删除数据库或回退数据需要单独确认。
