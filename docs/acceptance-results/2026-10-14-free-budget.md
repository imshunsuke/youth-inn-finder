# 免费额度核算 · 2026-10-14

结论：当前小范围内测的 D1 写入预算可行；公开流量没有人数上限，不能承诺任何访问量下都稳定免费。以下分别列出测量、假设和未完成项。

## 数据库存在哪里

线上使用 Cloudflare 托管的 D1，官方 Wrangler 2026-10-14 14:44 左右返回数据库大小 1,499,136 字节，运行区域为 APAC。没有证据确认具体城市。开发电脑上的 SQLite 是独立开发数据，电脑关机不会关掉线上数据库。

D1 免费额度是每天读取 500 万行、写入 10 万行，存储 5 GB；写入包括 INSERT、UPDATE、DELETE 和相关索引维护。每天 UTC 00:00（台北 / 上海 08:00）重置。此次瓶颈是每日操作量，空间尚很充足。来源：[D1 官方定价](https://developers.cloudflare.com/d1/platform/pricing/)。

`wrangler d1 info` 的 `rows_written_24h` 是滚动 24 小时，不能拿它当当前 UTC 日的额度用量。`scripts/d1-usage-report.mjs` 按 UTC 日查询官方 Query Insights，限制输出为分类、数字和时间，原始 SQL 不落盘；分析可能延迟或采样，不替代完整 D1 操作元数据。

## 一天的离线模型

执行真实应用 SQL、采集器、查询路由、限流、提醒检查与邮件出队代码，使用真 SQLite 和假官网 / 假邮件。没有访问官网、发送邮件或读取生产提醒。90 个驿站；提醒情景使用 10 条已验证的单站连续入住提醒；访客情景为每人每天两次不同的全市冷区间查询，每 10 秒查看进度，最多停留 10 分钟。缓存共享、15 分钟刷新、重试退避、优先级续期和每日官网请求上限均运行真实实现。

表格按本地触发器统计实际行变更，再估算索引维护：插入和删除每个索引加一；更新时对 SQL SET 涉及的每个索引分别计入删除和插入，即使赋值未变。此项偏保守，但仍是模型，**不是 D1 实际账单，也不是任意流量下的数学上限**。未包含任意恶意访问、用户不断改变查询条件、真实网络耗时和频繁管理提醒；预算应再留至少 20% 余量。

5 人正常情景再留 20% 余量约 46,609 行 / 天；持续区间失败情景约 59,587 行 / 天。25 人正常情景留余量后已接近上限，失败情景超过上限。这里的“人数”只是相应使用方式的例子，不能直接拿它作为精确服务容量：共享日期会省很多，频繁切换未查过的区间会更多。

两天无访客、无提醒模型用于检查固定后台不是只在首小时省写入；每日清理已过期的 HTTP 限流桶。真实提醒管理和多日令牌清理没有包含在一天模型中，保留的余量也用于这些操作。模拟没有把每日 6,000 次额外官网请求额度当作 D1 写入额度。50 人情景只完成了 67/100 个冷区间会话，另外 33 个在 10 分钟后放弃，不能把其较低工作量误称为全部查询完成。

复现（仅离线，不载入 `.env.local`）：

```bash
node scripts/quota-model.mjs 0,5,10,25 .data/optimization/daily-quota-model.json
```

持续失败和两天模拟通过 `modelDay({users:5,upstreamFails:true})`、`modelDay({users:0,reminders:0,days:2})` 调用。模型与元数据计数器有回归测试，包括索引字段解析、RETURNING 写入、原生批处理、UTC 重置、分析缺失、计数回退和敏感字段过滤。

## 线上验证与提前发现

写入优化版本 `307a87f`，部署 `b7087280-3ae5-4c4c-aa48-ea776ef66c6e`。70 分钟验收与逐分钟只读额度记录在 `.data/acceptance-20261014-discovery-run2/`；还包含空闲过期、重新采集和多个日期并行，不能把整段增长简单乘成全天后台基线。当前日包含旧版本和测试的历史消耗，也不能当作新版本正常一天的用量。

新增按次记录 D1 `meta.rows_written`、`meta.rows_read` 的计数器，包含 D1 返回的索引计费，记录只有数字、阶段和完整性标志，不记录 SQL、绑定参数、结果、邮箱或令牌。`first()` 用同一 SQL 的 `all()` 执行一次以取得元数据，保留第一行 / 第一列行为；应用缓存仍按原始数据库绑定复用。元数据缺失或操作失败不报告“完整的零用量”。`scripts/profile-d1.mjs` 用固定版本观察至少 20 分钟后台，跨过一次 15 分钟刷新周期；结果待填入，未完成前不声明实测已通过。

`scripts/d1-usage-report.mjs` 只对同一 UTC 日最近两小时、至少 20 分钟的完整分析样本预测重置前用量：达到 50% 且预计超过 80%，或实际达到 70%，提前提示。分析失效或计数回退不当作零。当前任务已设置每小时的只读额度观察，风险未变化保持安静，不重复同一告警；这依赖 Codex 本地自动化和已授权的 Wrangler 可运行，不是独立服务器端硬限制。

仅测试进程具有接近额度时停止的保护，不会暂停生产采集或邮件。用户尚未批准“预计超预算时暂停新的区间采集”，因此此保护尚未启用。邀请制只控制邮件提醒人数，不限制公开查房人数。

写入核算通过也不代表读取、CPU、邮件和服务可用性均通过。读取仍需核对每天 500 万行上限；免费 Worker 单次 CPU 风险另按实际运行记录报告。
